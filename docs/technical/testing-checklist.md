# Чек-лист тестирования: "Микро-триггеры внимания"

См. также: [технический бриф](micro-triggers-tech.md), [roadmap v2](../business/micro-triggers-roadmap-v2.md).

Ручной QA-чек-лист по всему функционалу приложения — для прохождения
человеком и как справочник для будущих QA-сессий (в т.ч. автоматизированных
через browser automation). Каждый пункт отмечать `[x]` при подтверждении.

## Подготовка окружения

- [ ] `docker-compose up -d` — локальный Postgres поднят (порт 5433)
- [ ] `npx prisma migrate status` — миграции применены (`Database schema is up to date!`)
- [ ] `npm run dev` (`shopify app dev`) — запущен, получен `Preview URL`
- [ ] App embed блок "Micro-triggers" включён на теме dev store
      (Admin UI → секция "Enable on your theme" → deep link в редактор темы)

**⚠️ Важно про звук**: Sound alert триггер реально проигрывает звук через
динамики при добавлении в корзину / переходе на checkout. Перед тестами со
звуком предупреждать/проверять, что это ожидаемо — не кликать "Add to cart"
многократно подряд без необходимости, особенно если рядом кто-то есть или
звук может быть неуместен в моменте.

## 1. Admin UI — сохранение настроек

Для каждого триггера: открыть `/app`, изменить значение, обновить страницу
(F5), убедиться что значение сохранилось (persist через Prisma upsert).

- [ ] Blinking browser tab: toggle, текст заголовка, интервал (ms)
- [ ] Exit-intent popup: toggle, текст попапа, промокод, sensitivity (px),
      countdown (сек)
- [ ] Sound alert: toggle, выбор пресета (Beep/Bell/Coin), "on add to cart",
      "on checkout page"
- [ ] Sticky back-to-cart bar: toggle, текст (с `{count}`)
- [ ] Low-stock badge: toggle, порог, текст (с `{count}`)
- [ ] Free shipping bar: toggle, порог (центы), текст прогресса (с
      `{remaining}`), текст успеха
- [ ] Email capture: toggle, текст приглашения

Альтернативная проверка сохранения — без визуального F5, читать актуальные
настройки напрямую через App Proxy (не требует авторизации в admin):
```
GET https://{shop}.myshopify.com/apps/micro-triggers/settings
```
Должен вернуть JSON со всеми 8 моделями и актуальными значениями.

## 3. Storefront — механика триггеров

Проверять на реальном dev store (`https://{shop}.myshopify.com`), товар с
`inventory_management: shopify` и наличием на складе. Добавлять товар в
корзину через UI один раз в начале блока, дальше переиспользовать корзину,
чтобы не плодить лишние "Add to cart" клики (см. предупреждение про звук
выше).

- [ ] **Blinking tab**: уйти с вкладки (переключиться) при непустой корзине →
      заголовок вкладки начинает чередоваться с настроенным текстом;
      вернуться на вкладку → заголовок восстанавливается
- [ ] **Sticky back-to-cart bar**: срабатывает при возврате на вкладку после
      blinking (если включён) — тёмная полоса сверху с `{count}`, кнопка
      закрытия (×) скрывает полосу
- [ ] **Exit-intent popup**: курсор уходит через верхнюю границу окна при
      непустой корзине → оверлей с текстом, промокодом, countdown (если
      включён), email-полем (если email capture включён), кнопкой "Close"
- [ ] **Sound alert**: submit формы `/cart/add` → звук проигрывается (если
      "on add to cart" включён); клик по ссылке на `/checkout` → звук
      проигрывается (если "on checkout page" включён). **Кликать
      осознанно** — см. предупреждение выше
- [ ] **Low-stock badge**: на странице товара с малым `inventory_quantity`
      (≤ порога) — бейдж появляется рядом с add-to-cart. На товаре без
      доступного `inventory_quantity` (нет inventory tracking или "Continue
      selling when out of stock") — бейдж не рендерится, без ошибок в
      консоли (честная деградация, не баг)
- [ ] **Free shipping progress bar**: полоса **закреплена снизу экрана**
      (`position: fixed; bottom: 0`), видна сразу при заходе на страницу
      товара при непустой корзине; обновляется через ~300мс после
      добавления в корзину; текст прогресса ниже порога, текст успеха на/выше
      порога. **Известный фикс**: раньше бар мог быть невидим на некоторых
      темах (см. журнал изменений ниже) — если полоса не видна снизу экрана,
      это регрессия
- [ ] **Email capture**: в exit-попапе — ввод email, кнопка "Submit" →
      запись должна появиться в таблице `CapturedLead` (проверка:
      `docker exec simple-app-postgres-1 psql -U micro_triggers -d
      micro_triggers_dev -c "SELECT * FROM \"CapturedLead\" ORDER BY
      \"createdAt\" DESC LIMIT 5;"`). **Важно**: фича только собирает лиды
      для мерчанта — она не отправляет письмо/промокод на введённый email
      автоматически (нет интеграции с email-провайдером). Кнопка и текст
      сформулированы честно ("Submit"/"Leave your email"), без обещания
      отправки
- [ ] **Captured emails (Admin UI)**: секция под "Email capture in exit
      popup" в `/app` показывает таблицу последних 50 собранных email с
      датой — обновить страницу после теста email capture выше и убедиться,
      что новая запись видна в списке

## Способы тестирования без ложных кликов/звука

- **Проверка persist настроек**: `GET /apps/micro-triggers/settings` через
  App Proxy — не требует UI-взаимодействия.
- **Проверка добавления в корзину без submit формы** (не триггерит звук,
  если нужно изолированно проверить что-то другое):
  `POST /cart/add.js` с телом `{items: [{id: <variant_id>, quantity: 1}]}` —
  это XHR/fetch, не проходит через `<form submit>`, поэтому слушатель звука
  на `submit` не сработает.
- **Проверка blinking tab без реального переключения вкладок**: в консоли
  браузера (DevTools, не через автоматизацию) —
  `document.dispatchEvent(new Event('visibilitychange'))` после подмены
  `document.hidden` через `Object.defineProperty`.
- **Проверка exit-intent без реального движения курсора за край окна**: код
  слушает `mouseout` на `document`, не `mouseleave` — событие должно иметь
  `relatedTarget: null` и `clientY <= sensitivityPx`.
- **Проверка fixed-элементов (sticky bar, free shipping bar, exit popup) на
  скриншотах**: известная проблема инструментов автоматизации — скриншот
  иногда не отражает элемент, добавленный в DOM динамически, до следующего
  реального repaint. Не доверять единственному скриншоту при "элемент не
  виден" — сначала проверить `getBoundingClientRect()` и
  `getComputedStyle()` через JS, и только потом делать вывод о баге.

## Журнал изменений (после тестов)

- **2026-09-10**: найден и исправлен баг free shipping bar — селектор
  `[id*="cart-drawer" i], [class*="cart-drawer" i]` ложно совпадал с
  невидимой секцией темы "Savor" (`#shopify-section-cart-drawer-section`,
  обычный блок в потоке страницы, а не floating-виджет). Бар физически
  существовал в DOM с верным текстом, но был невидим для посетителя без
  прокрутки в самый низ страницы. Исправлено: бар всегда рендерится как
  `position: fixed; bottom: 0`, без попытки угадать разметку темы — тем же
  паттерном, что уже надёжно работает у sticky back-to-cart bar (`top: 0`).

- **2026-09-10**: email capture собирал лиды в БД, но нигде не показывал их
  мерчанту в Admin UI — данные технически были недоступны владельцу магазина
  (потенциальный конфликт с требованием Shopify App Store 5.1.5 "Send
  collected data back to the merchant"). Плюс текст кнопки "Send me the
  code" обещал отправку письма с промокодом, которой в коде не было — фича
  только сохраняет email, без интеграции с email-провайдером. Исправлено:
  добавлена секция "Captured emails" в `/app` (таблица последних 50 email с
  датой, читается напрямую из `CapturedLead` в loader'е); текст кнопки и
  дефолтный текст приглашения изменены на честные ("Submit"/"Leave your
  email", без обещания отправки) — в JS, loader-дефолте и Prisma-схеме
  (миграция `20260910081837_email_capture_honest_default_text`).
