# План развития v2: "Микро-триггеры внимания"

См. также: [бизнес-брифа v1](micro-triggers-brief.md),
[технический бриф v1](../technical/micro-triggers-tech.md),
[разведка конкурентов](competitor-research.md).

MVP v1 (три триггера, Admin UI, billing, прод-хостинг на Railway) готов и
близок к сабмиту — см. итоговый статус в конце технического брифа. Этот файл
фиксирует идеи расширения функционала, обсуждённые после MVP.

**Причина реализации всего v2 разом**: $9/мес субъективно ощущался как
завышенная цена относительно первоначального функционала (3 простых
триггера) — решено закрыть весь Приоритет 1 и Приоритет 2 одним заходом,
чтобы оправдать цену набором фич, прежде чем поднимать вопрос о самой цене.

## Приоритет 1 — малое усилие, сразу повышают ощутимую ценность

- [x] **Выбор звукового сигнала при добавлении в корзину** — реализовано,
  2026-09-08, ветка `dev`. Три пресета (`beep`/`bell`/`coin`) на чистом Web
  Audio (разная частота/последовательность нот), без аудиофайлов — сохраняет
  принцип "лёгкий бандл, без зависимостей". Выбор через `s-select` в Admin UI,
  новое поле `SoundTrigger.soundPreset` в Prisma.

- [x] **Sticky "back to cart" бар** — реализовано, 2026-09-08, ветка `dev`.
  Новая модель `StickyCartBarTrigger`. Полоса вверху страницы с текстом
  (`{count}` — число товаров в корзине из `cart.js`), показывается при
  возврате на вкладку после срабатывания мигающей вкладки.

- [x] **Countdown-таймер в exit-попапе** — реализовано, 2026-09-08, ветка
  `dev`. Новое поле `ExitPopupTrigger.countdownSeconds` (0 = выключен),
  обратный отсчёт под промокодом в попапе, чистый фронтенд.

- [x] **Настраиваемая задержка/чувствительность триггеров** — реализовано,
  2026-09-08, ветка `dev`. Новые поля `ExitPopupTrigger.sensitivityPx`
  (ранее захардкожено `clientY <= 20`) и `BlinkingTabTrigger.intervalMs`
  (ранее захардкожено 1000мс), настраиваются в Admin UI через
  `s-number-field`, прокинуты через `proxy.settings.tsx`.

- [x] **Превью в самом Admin UI** — реализовано, 2026-09-08, ветка `dev`.
  Статический мини-макет exit-попапа (текст, промокод, countdown,
  email-поле) и мигающей вкладки прямо на странице настроек через inline
  CSS, без похода на витрину. Закрывает компромисс "нет inline-превью" из
  шага 4 MVP v1 (живой iframe невозможен из-за `frame-ancestors` CSP
  витрины).

## Приоритет 2 — среднее усилие, новые лёгкие JS-only триггеры

- [x] **Low-stock / social-proof бейдж** — реализовано, 2026-09-08, ветка
  `dev`. Новая модель `LowStockBadgeTrigger`. Работает на странице товара
  через публичный `/products/{handle}.js` (`inventory_quantity` по
  варианту) — без новых Admin scopes. Ограничение: показывается только если
  у мерчанта включён inventory tracking в Shopify и не включено "Continue
  selling when out of stock" — иначе `inventory_quantity` недоступен и
  бейдж просто не рендерится (не баг, а честная деградация).

- [x] **Free shipping progress bar** — реализовано, 2026-09-08, ветка `dev`.
  Новая модель `FreeShippingBarTrigger`. Полоса в корзине/drawer через
  `/cart.js` (`total_price`), обновляется при добавлении товара.

- [x] **Cart abandonment email capture в exit-попапе** — реализовано,
  2026-09-08, ветка `dev`. Новая модель `EmailCaptureTrigger` (настройки) +
  `CapturedLead` (собранные лиды). Поле email в exit-попапе, новый публичный
  endpoint `app/routes/proxy.lead.tsx` (App Proxy, `authenticate.public.appProxy`,
  без новых Admin scopes) сохраняет лид в Postgres через существующий
  Prisma-паттерн.

## Приоритет 3 — апгрейд тарифа (существенное усилие)

Эти пункты уже отмечены в v1-брифе как кандидаты на дорогой тариф — здесь
просто собраны вместе для видимости:

- **Push-уведомления браузера** (service worker) — отдельная техническая
  сложность, оправдывает более высокую цену.
- **Аналитика по триггерам** — сколько раз показан попап, сколько конверсий
  по промокоду. Требует таблицу событий в Postgres и отдельную секцию с
  графиками в Admin UI.

## Статус

Приоритет 1 и Приоритет 2 реализованы целиком, 2026-09-08, в ветке `dev`
(намеренно не в `main` — приложение сейчас проходит ревью Shopify App Store
на существующем MVP v1, заливать изменения функционала в процессе ревью
рискованно). См. подробности реализации, миграцию БД и оставшиеся ручные шаги
(применение миграции к прод-БД, QA на витрине, слияние в `main`) в
[техническом брифе](../technical/micro-triggers-tech.md).

Приоритет 3 остаётся черновым списком идей на будущее — не начат.
