# План развития v2: "Микро-триггеры внимания"

См. также: [бизнес-брифа v1](micro-triggers-brief.md),
[технический бриф v1](../technical/micro-triggers-tech.md),
[разведка конкурентов](competitor-research.md).

MVP v1 (три триггера, Admin UI, billing, прод-хостинг на Railway) готов и
близок к сабмиту — см. итоговый статус в конце технического брифа. Этот файл
фиксирует идеи расширения функционала, обсуждённые после MVP, до того, как
они превратятся в конкретные задачи в работе.

## Приоритет 1 — малое усилие, сразу повышают ощутимую ценность

- **Выбор звукового сигнала при добавлении в корзину** — сейчас
  `SoundTrigger` всегда играет один и тот же сгенерированный Web Audio бип
  (880Hz синус, см. `micro-triggers.js`). Дать мерчанту выбор из нескольких
  готовых коротких звуков (2-4 варианта: например "бип", "колокольчик",
  "монетка") прямо в Admin UI через `s-select` рядом с существующими
  тумблерами `playOnAddCart`/`playOnCheckout`. Технически: поле
  `soundFileUrl` в модели `SoundTrigger` уже зарезервировано под это в схеме
  (`prisma/schema.prisma`) — есть два пути:
  - генерировать разные пресеты чистым Web Audio (разная частота/огибающая/
    последовательность нот) без аудиофайлов — сохраняет принцип "лёгкий
    бандл, без зависимостей";
  - либо использовать реальные короткие аудиофайлы (несколько KB каждый) из
    `extensions/micro-triggers-storefront/assets/`, тогда `soundFileUrl`
    хранит имя пресета, а не произвольный URL мерчанта (без пользовательской
    загрузки файлов, чтобы не открывать хранилище).
  Рекомендация: начать с пресетов на чистом Web Audio — не требует новых
  ассетов и сохраняет позиционирование "кило-, не мегабайты".

- **Sticky "back to cart" бар** — тонкая полоса сверху/снизу с "У вас N
  товаров в корзине" при возврате на вкладку после того, как мигающая вкладка
  сработала. Использует уже собираемые данные (`cart.js`), новый компонент
  минимален.

- **Countdown-таймер в exit-попапе** — "Промокод действует 10 минут" с
  обратным отсчётом. Чисто фронтенд, использует уже существующее поле
  `discountCode`.

- **Настраиваемая задержка/чувствительность триггеров** — сейчас
  `clientY <= 20` (порог exit-intent) и интервал мигания 1000ms захардкожены
  в `micro-triggers.js`. Добавить поля в существующие Prisma-модели, прокинуть
  через уже существующий паттерн upsert в `app._index.tsx` и через
  `proxy.settings.tsx`.

- **Превью в самом Admin UI** — раз живой iframe невозможен (CSP,
  зафиксировано в техброфе), сделать статический мини-макет попапа/мигающей
  вкладки прямо на странице настроек через CSS/JS, без похода на витрину.
  Закрывает известный компромисс "нет полноценного inline-превью" из шага 4.

## Приоритет 2 — среднее усилие, новые лёгкие JS-only триггеры

- **Low-stock / social-proof бейдж** — "Осталось всего 3 шт." рядом с кнопкой
  добавления в корзину. Требует product/variant inventory — через
  Storefront API без новых Admin scopes (product JSON), либо через App Proxy
  проксировать Admin API запрос.

- **Free shipping progress bar** — "Добавьте ещё $15 до бесплатной доставки"
  в мини-корзине. Хорошо ложится в позиционирование "3 лёгких триггера в
  одном", отличает от тяжёлых конкурентов.

- **Cart abandonment email capture в exit-попапе** — поле email вместо/вместе
  с промокодом. Требует минимальный backend endpoint для сохранения лида —
  Prisma+Postgres уже есть, паттерн такой же, как у остальных моделей.

## Приоритет 3 — апгрейд тарифа (существенное усилие)

Эти пункты уже отмечены в v1-брифе как кандидаты на дорогой тариф — здесь
просто собраны вместе для видимости:

- **Push-уведомления браузера** (service worker) — отдельная техническая
  сложность, оправдывает более высокую цену.
- **Аналитика по триггерам** — сколько раз показан попап, сколько конверсий
  по промокоду. Требует таблицу событий в Postgres и отдельную секцию с
  графиками в Admin UI.
